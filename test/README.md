# test

Интеграционные тесты модуля `network` на Terratest.

## Эти тесты создают реальные ресурсы в реальном аккаунте AWS

Каждый прогон поднимает VPC, подсети трёх уровней в двух зонах, интернет-шлюз, NAT-шлюзы
с Elastic IP, роль IAM и log-группу CloudWatch — и затем всё это удаляет. Это стоит денег:
NAT-шлюз тарифицируется по часам с момента создания, и три теста запускаются параллельно.

Офлайн-режима нет и не может быть. `terraform plan` с провайдером AWS всё равно требует
учётных данных: провайдер конфигурируется до планирования и обращается к STS. Поэтому:

- **в CI** выполняется только `go vet ./...` — он компилирует тестовый пакет и проверяет
  его статически. Ошибка в имени выхода или в сигнатуре хелпера ловится здесь;
- **вручную**, против песочницы, выполняется `make test`.

```bash
export AWS_PROFILE=sandbox
export AWS_REGION=eu-central-1
make test
```

Тесты используют регион `eu-central-1`, CIDR `10.99.0.0/16` и префикс имени `tt-<random>`,
чтобы параллельные прогоны не конфликтовали за глобально уникальные имена — log-группу и
роль IAM. `defer terraform.Destroy` стоит до `InitAndApply`, поэтому ресурсы удаляются и
при провалившемся ассерте.

Если прогон прерван и `destroy` не отработал, оставшиеся ресурсы находятся по тегу
`purpose = terratest`.

## Что именно проверяется

| Тест | Утверждение |
|---|---|
| `TestNetworkSingleNATGateway` | при `single_nat_gateway = true` шлюз ровно один и стоит в первой зоне; приватные подсети при этом не публичны |
| `TestNetworkNATGatewayPerAZ` | при `single_nat_gateway = false` шлюзов столько же, сколько зон, и Elastic IP у каждого свой |
| `TestNetworkSubnetTiers` | публичные подсети маршрутизируют `0.0.0.0/0` в интернет-шлюз, intra-подсети — нет; всего подсетей три на зону; имя log-группы совпадает с ожидаемым |

Проверяется поведение, а не факт создания: «шлюзов столько же, сколько зон, и адреса
у них разные» — это то, ради чего переключатель существует. «Ресурс создался» тестом
не считается.

## Что не покрыто

Модули `eks`, `rds` и `s3-cloudfront` тестами не покрыты. Прогон EKS — это около
пятнадцати минут на создание и столько же на удаление, RDS Multi-AZ — больше двадцати.
Честнее сказать, что этого здесь нет, чем написать тест, который никто не запускает.
Их контракт проверяется `validate`, `tflint`, `checkov` и блоками `validation`.
